# Анализ проекта kg_controller: уязвимости и план рефакторинга

## 1. Паспорт проекта и контекст платформы

* **Целевой МК**: Texas Instruments **TMS320F28377S** (C28x 32-bit DSP, FPU32, TMU0, VCU2).
* **Среда разработки**: Code Composer Studio v11 (`C:\ti\ccs1120`, компилятор `TI v21.6.0.LTS`).
* **SDK**: `C2000Ware_4_01_00_00` (SysConfig `c2000.syscfg`, DriverLib, F021 Flash API).
* **Специфика C28x**:
  * 1 байт = **16 бит** (`sizeof(char) == 1`, `sizeof(uint16_t) == 1`, `CHAR_BIT == 16`).
  * 32-битные типы (`uint32_t`, `float`) занимают **2 слова** (`sizeof == 2`).
  * Работа с Flash требует управления насосом накачки FMC0/FMC1 и F021 API.
* **Назначение**: Контроллер геофизического каротажного прибора (картографирование границ пластов, электромагнитный каротаж во время бурения LWD/Cartograph, скважинная инклинометрия).
* **Интерфейсы**:
  * **CAN-A**: обмен с модулями генераторов (Tx) и измерителей (Rx).
  * **SPI-A / SPI-C**: акселерометр ADXL355, гироскоп L3GD20, магнитометр MMC5983.
  * **SCI-A (Bluetooth)**: технологический канал калибровки и отладки.
  * **SCI-C (EXT)**: основной проводной канал телеметрии и команд скважинного зонда.

## 2. Каталог дефектов и уязвимостей

### 🔴 Категория P0: Критические дефекты (Crash / HardFault / затирание памяти)

#### 1. Затирание системной памяти ядра через ошибочный `memset`
* **Файл**: `debug_print.c`, строка 188.
* **Код**:
  ```c
  memset((void*)UartCmd.buf[0], 0x00, 512);
  ```
* **Суть дефекта**: Вместо адреса массива передан его нулевой элемент, приведенный к указателю. При значении первого байта `0` или ASCII-кода команды (`'A'` = `0x0041`) функция `memset` затирает 512 слов в системной нулевой странице памяти микроконтроллера (векторы, критические переменные, системные регистры).
* **Последствие**: Немедленный сбой, зависание ядра или HardFault при приеме любой команды по Bluetooth.
* **Устранение**:
  ```c
  memset(UartCmd.buf, 0x00, sizeof(UartCmd.buf));
  ```

#### 2. Переполнение буферов фильтрации скользящего среднего
* **Файл**: `int_data_ready.c`, строки 53, 73, 226–252.
* **Суть дефекта**: Массивы `G_Data[32]`, `M_Data[32]`, `W_Data[32]`, `g_modul_buff[32]`, `m_modul_buff[32]`, `w_modul_buff[32]` объявлены на 32 элемента. При этом в функции `CheckMetroData` (в `main.c`) параметры окна `MA_WINDOW_SIZE` и `MLD_WINDOW_SIZE` валидируются на диапазон **до 256**. Если из Flash или по UART задан размер окна > 32, прерывание таймера 1 мс выходит за пределы массивов и разрушает смежные переменные ОЗУ.
* **Устранение**: Ограничить диапазон в `CheckMetroData`: `MA_WINDOW_SIZE <= 32` либо увеличить массивы до 256 элементов.

#### 3. Переполнение приемных буферов UART в прерываниях (Buffer Overflow)
* **Файл**: `uart.c`, строки 86–88, 144–149.
* **Суть дефекта**:
  * В `INT_UartExt_RX_ISR`: запись в `RxBufferExt[idx]` выполняется без проверки границы `idx < UART_BUF_SIZE`. При помехе на линии индекс растет непрерывно, разрушая память за пределами буфера 2048 слов.
  * Вызов `memcpy(&UartCmdExt.buf, RxBufferExt, len)` не проверяет `len <= sizeof(UartCmdExt.buf)`.
  * В `INT_UartBT_RX_ISR`: буфер `RxBufferBT[256]` заполняется без проверки границы `idx < 256`.
* **Устранение**: Ввести жесткий guard:
  ```c
  if (idx >= UART_BUF_SIZE) {
      idx = 0;
      len = 0;
  }
  ```

### 🟠 Категория P1: Архитектурные и логические сбои

#### 4. Неатомарное чтение/модификация 64-битного времени `Now` (Race Condition)
* **Файлы**: `main.c`, `cyclogram.c`, `uart.c`, `int_data_ready.c`.
* **Суть дефекта**: `volatile uint64_t Now` инкрементируется в прерывании таймера `INT_TIMER1_1MS_ISR`. На 32-битном ядре C28x чтение и запись 64-битной переменной занимают несколько инструкций. В циклограмме и основном цикле выполняются проверки `Now > TimePrint`, `Now > gPktTimeEXT + 5` без запрета прерываний. При попадании прерывания между чтением младшего и старшего слов происходит разрыв времени (скачок на 4.29 млрд мс), что срывает циклограмму и таймауты связи.
* **Устранение**: Сделать безопасный геттер с отключением прерываний или перейти на 32-битный счетчик миллисекунд (хватает на 49.7 суток непрерывной работы).

#### 5. Символ кириллицы в имени поля структуры `wc.СycleStartTime_ms`
* **Файлы**: `_globals.h` (строка 221), `cyclogram.c` (строки 234, 411, 791).
* **Суть дефекта**: Имя поля написано с использованием русской буквы «С» (`0xD0 0xA1` в UTF-8) вместо латинской «C». Вызывает зависимость от локали и ошибки при сборке компилятором.
* **Устранение**: Заменить идентификатор на `cycleStartTime_ms`.

#### 6. Распаковка структуры при приеме профиля LWD
* **Файл**: `external_cmd.c`, строка 378.
* **Статус**: 🟢 **ШТАТНОЕ ПОВЕДЕНИЕ (НЕ ТРОГАТЬ, ТАК И ДОЛЖНО БЫТЬ)**
* **Код**:
  ```c
  sz = sizeof(struct METROLOGY_GP) + 1;
  PackBuffer((uint16_t*)(&(UartCmdExt.buf[3])), (uint16_t*)(&Metro), sz);
  ```
* **Примечание**: Распаковка в `&Metro` является проектной архитектурной особенностью протокола прибора, код оставлен в исходном виде без изменений.

#### 7. Блокирующие задержки и стирание Flash без защиты прерываний
* **Файл**: `inc_flash.c`, функции `FLASH_WriteCal`, `FLASH_WriteMetrology`, `FLASH_WriteSetOfPresets`.
* **Суть дефекта**: При прошивке отключается только `TIMER0_1MS_BASE`, тогда как прерывания UART и CAN остаются активными. Если во время стирания/записи сектора сработает ISR, чей код или векторы не перемещены в RAM, произойдет аппаратный конфликт шины Flash (Bus Collision).
* **Устранение**: Оборачивать критические секции Flash API макросами `DINT;` / `EINT;` и гарантировать размещение кода ISR в `.TI.ramfunc`.

### 🟡 Категория P2: Логические ошибки математики и протоколов

#### 8. Избыточный двойной вызов численного расчета `RO_ARG`
* **Файл**: `cyclogram.c`, строки 724–733.
* **Суть дефекта**: В циклограмме дважды подряд вызывается ресурсоемкий численный метод бинарного поиска сопротивления `RO_ARG` с расчетом комплексных экспонент и корней.
* **Устранение**: Удалить дублирующий цикл.

#### 9. Затенение переменной цикла в компрессии данных
* **Файл**: `data_compress.c`, строки 173–181.
* **Суть дефекта**: Во внешнем цикле `for(int n = n_0; n < n_end; n++)` объявлен внутренний цикл `for(uint16_t n = 0; n < packed.bits; n++)` с тем же именем переменной `n`.
* **Устранение**: Переименовать переменную внутреннего цикла в `bit_idx`.

#### 10. Риск деления на ноль в векторной математике
* **Файл**: `math_angles.c`, функции `vctr_cos` и `mtrx_1`.
* **Суть дефекта**: Отсутствует проверка модулей векторов на `0.0f` и детерминанта матрицы `det` на близость к нулю (`fabsf(det) < 1e-9f`). В случае нулевого ускорения формируются значения `NaN`/`Inf`, разрушающие расчет углов инклинометра.
* **Устранение**: Добавить проверку эпсилон и возврат безопасного значения при вырожденных данных.

### 🟢 Категория P3: Метрология магнитометра MMC5983MA и тайминги выборки

#### 11. Компенсация мостового смещения (Null Field Offset) и температурного дрейфа MMC5983MA
* **Файлы**: `MMC5983_spi.h`, `MMC5983_spi.c`, `int_data_ready.c`.
* **Статус**: ✅ **ИСПРАВЛЕНО (скомпилировано, ожидает аппаратной верификации на приборе)**
* **Суть дефекта**:
  * При отключении питания и при нагреве на 1–2% в час кремниевый пермаллоевый мост кристалла MMC5983MA накапливает небаланс нуля (Null Field Offset до ±800 кодов в 18-битном режиме).
  * В непрерывном режиме на 1000 Гц датчик аппаратно не делает парных замеров SET/RESET, поэтому смещение моста попадало в выходной сигнал и искажало расчет угла тулфейса и азимута `angle_azm`.
* **Выполненное решение**:
  1. В `MMC5983_spi.c` реализована функция аппаратной калибровки нуля моста `MMC5983_CalibrateBridge(void)`:
     * Перевод в режим One-Shot (`Cmm_en = 0`).
     * Импульс SET катушки -> замер при прямой намагниченности M_SET.
     * Импульс RESET катушки -> замер при обратной намагниченности M_RESET.
     * Расчет оффсета: Bridge_Offset_i = (M_SET_i + M_RESET_i) / 2.
     * Возврат в рабочее состояние SET и включение Continuous Mode с Auto_SR_en = 1 в регистре 0x09.
  2. В `MMC5983_ReadXYZ()` сырые коды автоматически корректируются: M_i = raw_i - Bridge_Offset_i.
  3. В `MMC5983_Init()` калибровка нуля моста выполняется сразу при включении прибора.
  4. В `int_data_ready.c` в блоке детектора стоянки (`!bIsMoving`) реализована периодическая автокалибровка моста раз в 60 с либо при изменении температуры по встроенному термодатчику `Tout` (регистр 0x07) на |Delta T| >= 2 degC.

#### 12. Разделение частот: гарантированная частота опроса датчиков 950 Гц
* **Файлы**: `c2000.syscfg`, `CPU1_FLASH/syscfg/board.c`, `CPU1_RAM/syscfg/board.c`, `int_data_ready.c`.
* **Статус**: ✅ **ИСПРАВЛЕНО (скомпилировано, ожидает аппаратной верификации на приборе)**
* **Суть дефекта**:
  * Внутренний RC-генератор АЦП MMC5983MA имеет технологический и температурный разброс (до +-10..15%). При частоте опроса процессором строго 1000 Гц (1.000 мс) возникают биения с генератором датчика, приводящие к фазовому дрожанию (джиттеру) и риску считывания незавершенной выборки.
* **Выполненное решение**:
  1. Таймер системного времени `TIMER1_1MS_BASE` (`Now++`) оставлен строго на **1000 Гц (1.000 мс)** для сохранения эталонных таймаутов протоколов связи UART, CAN и циклограммы.
  2. Период таймера опроса датчиков `TIMER0_1MS_BASE` настроен на **950 Гц** (`CPUTimer_setPeriod = 105263U` при 100 МГц, период T = 1.05263 мс в `c2000.syscfg` и `board.c`), что гарантированно перекрывает время АЦП магнитометра.
  3. В `int_data_ready.c` введена константа `#define SENSOR_SAMPLE_RATE_HZ 950.0f` и скорректирован шаг интегрирования угловой скорости гироскопа:
     `Wg_1000 = Wg / SENSOR_SAMPLE_RATE_HZ;`
     и в эмуляции вращения:
     `MTF = MTF - ((gEmulRotateSpeed * PI) / (30.0 * SENSOR_SAMPLE_RATE_HZ));`
     устранив 5.26%-ную ошибку угла.

```
                                │

 │                  ОБРАБОТКА ДАННЫХ И МАТЕМАТИКА               │

                                │

 │ hal_can.c     hal_uart.c     hal_flash.c    sensors_spi.c    │
 └──────────────────────────────────────────────────────────────┘
```

1. **Разделение заголовочных файлов**: Разбить монолитный `_globals.h` на компактные заголовочные файлы: `app_types.h`, `metro_types.h`, `cyclogram.h`.
2. **Разгрузка критического прерывания 1 мс**: Оставить в `INT_TIMER0_1MS_ISR` только опрос SPI-датчиков в кольцевой буфер. Вычисление углов, фильтрацию MLD и полиномиальный предиктор перенести в фоновый цикл `main()`.
3. **Безопасность bootloader**: Защитить команду `EXT_CMD_ENTER_BOOTLOADER` обязательным 32-битным ключом авторизации.
